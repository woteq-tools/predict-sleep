# Project Plan: Sleep Predictor PWA

## Git workflow (used for every step)

- `main` always holds working code.
- Each phase gets its own branch. Each step is one commit.
- When a phase is done, merge it into `main` with `--no-ff` and tag it.

```bash
# Start of a phase
git switch main
git switch -c phase-N-name

# End of every step
git add -A
git commit -m "type: short description"

# End of a phase
git switch main
git merge --no-ff phase-N-name -m "Merge phase N: name"
git tag -a vN.0 -m "Phase N complete"
```

Commit prefixes: `chore:` (setup), `feat:` (feature), `fix:` (edge case), `docs:`, `test:`, `style:`.

**Branch:** `phase-1-core-logic`

Keep this logic as pure functions so it is easy to test.

| Step | Task | Commit |
|---|---|---|

## Phase 5: Edge cases
**Branch:** `phase-5-edge-cases`

| Step | Task | Commit |
|---|---|---|
| 5.1 | **Double tap:** if a wake-up was recorded recently (for example within the last 4 hours), ask "Replace the current wake-up time?". Also debounce rapid taps. | `fix: handle repeated wake-up taps` |
| 5.2 | **Undo:** show a short-lived "Undo" toast after recording, restoring the previous value. | `feat: add undo for wake-up action` |
| 5.3 | **Next-day bedtime:** if the predicted bedtime's date differs from today's, label it "11:00 PM (tomorrow)". | `fix: label bedtimes that fall on the next day` |
| 5.4 | **Time zone changes:** timestamps are stored as absolute epoch values, so re-render on `visibilitychange` and on the `focus` event to pick up the new zone. Optionally save the zone at wake time and show a note if it differs. | `fix: handle time zone changes` |
| 5.5 | **Overdue state:** when bedtime has passed, show "Bedtime was 20m ago" instead of a negative countdown. | `fix: handle bedtime already passed` |

## Phase 6: Optional features
**Branch:** `phase-6-optional`

| Step | Task | Commit |
|---|---|---|
| 6.1 | **History data layer:** store entries `{wakeMs, bedtimeMs, awakeMinutes}` in an array. Cap at around 60 entries. | `feat: store wake-up history` |
| 6.2 | **History UI:** a list of past wake-ups and predicted bedtimes, with a "Clear history" button. | `feat: add history view` |
| 6.3 | **Notification permission:** request it from a user gesture (a settings toggle), not on load. | `feat: add notification permission toggle` |
| 6.4 | **Reminder:** schedule a notification at bedtime minus 30 minutes using `registration.showNotification` and a `setTimeout` while the app is open. | `feat: notify 30 minutes before bedtime` |

**Limitation:** a PWA can't reliably fire a *scheduled* local notification when the app is fully closed. The Notification Triggers API was discontinued, and true background delivery needs a push server, which this project deliberately avoids. Step 6.4 works while the app is open or recently backgrounded. If you want guaranteed delivery later, that would need a small backend or a different approach.
